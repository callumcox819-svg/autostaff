# Входящая почта — сборка с нуля

Старый стек (strict bind, fuzzy, фото, десятки fallback) **убран**. Дальше добавляем только то, что явно описано в шаге.

## Правило (жёстко)

- **1 validated email → 1 Offer / 1 OfferEmail** на пользователя. Повторная валидация того же **имени** (Gnimor) или того же **email** (`gnimor@gmx.ch`) — пропуск.
- Личный **ЧС** (`seller_blacklist`) + имена с уже сохранённым `OfferEmail`.
- Входящее IMAP: лот только если в БД **ровно одна** строка `OfferEmail` на этот `From` (дубликаты = ошибка данных, карточка без лота).

**Что делает бот**

1. IMAP-worker читает новые письма.
2. В PostgreSQL пишется `IncomingMail`: ящик, `from`, тема, текст, `imap_uid`.
3. В Telegram уходит **одна карточка**:
   - кому (inbox / имя отправителя рассылки),
   - от кого,
   - тема,
   - текст,
   - кнопки: **Перевести**, **Написать ещё**.
4. Кнопка **«Создать ссылку»** временно отключена (вернём на шаге 3).

**Чего нет**

- `resolved_offer_id`, лот, цена, сервис, фото.
- Привязка к `/send`, OfferEmail, журналу рассылки.

**Файлы**

- Логика карточки: `services/incoming_mail_worker.py` (`render_mail_text_chunks`, `build_kb`).
- Заглушки резолвера: `services/incoming_lead_resolve.py`.

---

## Шаг 1 — журнал «мы писали этому email» (план)

При `/send` уже есть `MailingSendLog`. На входящем:

- `From` → нормализованный email продавца.
- Если есть **хотя бы одна** строка журнала на этот email → помечаем письмо «известный контакт» (флаг в БД или поле `mailing_bound` без offer_id).

Без угадывания лота по fuzzy.

---

## Шаг 2 — один validated email → один лот (**сделано**)

`From` = email из `OfferEmail` после валидации → `resolved_offer_id`, в карточке **Лот / Товар / Цена / Сервис**, тема карточки = **item_title**. Заголовок «Получено…» = **Gnimor (имя рассылки)**. Фото — только на **первое** входящее по этому лоту; повторные письма — те же данные + «Создать ссылку».

Код: `services/incoming_validated_offer.py`, привязка в `incoming_mail_worker.py`.

---

## Шаг 3 — тема Re: = товар (план)

Несколько лотов на один seller email:

- из темы (`Re: … OFFER …`) достаём название (те же пресеты, что `/send`),
- ищем лот **только** среди лотов этого продавца (validated + journal),
- совпадение по title / sent subject, без подстрок типа `nes` в `hemnes`.

---

## Шаг 4 — фото (план)

Только если в шаге 2/3 лот найден и это **первое** входящее по этому `resolved_offer_id` — отдельное сообщение с фото из `Offer`.

---

## Шаг 5 — «Создать ссылку» (план)

Кнопка снова в клавиатуре. Берёт `resolved_offer_id` из `IncomingMail` (шаги 2–3), без повторного fuzzy-resolver.

---

## Деплой

Как раньше: **bot** + **imap-worker**, одна `DATABASE_URL`. После каждого шага — redeploy обоих сервisов.
